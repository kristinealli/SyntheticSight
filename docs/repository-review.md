# Repository Review and Consolidation Notes

This document records the code-quality review performed when converting the supplied team repository into the employer-facing final package.

## High-priority findings

### 1. Bundled checkpoint did not match the final run

The original archive contained two identical copies of `best_resnet50.pth` (API and Streamlit), SHA-256:

```text
3a74dd6f1c01ee093d977416718d938cb34aa14899b4d82ddf300a9090478390
```

Observed metadata / state-dict contract:

- epoch `9`;
- monitor value ≈ `0.89865` Fake F1;
- threshold `0.50`;
- head: `Linear(2048→256) → ReLU → Dropout(0.40) → Linear(256→1)`;
- no final `head_configuration` metadata.

The executed final training notebook and presentation instead document:

- selected epoch `13`;
- threshold `0.51`;
- head: `Linear(2048→256) → BatchNorm1d → ReLU → Dropout(0.30) → Linear(256→1)`;
- final test accuracy / Fake F1 `99.69%` and ROC-AUC `99.995%`.

**Resolution:** the legacy deployment binary was excluded rather than silently renamed. The true final checkpoint was subsequently recovered from the prior `deepfake_detection_checkpoints` artifact archive generated by `training_exploration_reinteration_kristine.ipynb`. It reports epoch `13`, checkpoint version `2`, BatchNorm + Dropout `0.30`, and threshold `0.51`, and it passes `scripts/verify_checkpoint.py`. The verified checkpoint is now included as `models/best_resnet50.pth`.

### 2. Deployment code had conflicting implementations

The supplied repository included:

- a Streamlit `app.py` importing a function that its local `inference.py` did not define;
- a separate ONNX Streamlit app with threshold `0.45`;
- tiny ONNX files that were not runnable model binaries in the supplied archive;
- an API with an older classifier head and cwd-dependent model path;
- an unfinished Vite/React frontend that was not required by the final presentation.

**Resolution:** one shared PyTorch inference package now supplies the model architecture, preprocessing, checkpoint validation, and threshold logic to both Streamlit and FastAPI.

### 3. Result artifacts were stale

The original root CSVs contained an older evaluation (including threshold `0.78` and ~98.2% test accuracy), conflicting with the final executed notebook and presentation.

**Resolution:** final result CSVs were regenerated from the final presentation/notebook values and clearly label their sources.

### 4. Documentation scaffolding was incomplete

The original `docs/references.md` and root `requirements.txt` were effectively empty, and `notebooks/README.md` was a placeholder.

**Resolution:** the final package includes a structured README, architecture/data/evaluation/bias/deployment docs, references, minimal dependency files, model metadata, and verification instructions.

## Final training provenance

The executed source notebook that produced the final model was originally named `training_exploration_reinteration_kristine.ipynb` (including the original filename spelling). It wrote training artifacts to `/content/drive/MyDrive/deepfake_detection_checkpoints/`, including `best_resnet50.pth`, validation/test predictions, metrics, the sampling manifest, and error-image folders. The polished repository keeps a consolidated final notebook at `notebooks/01_resnet50_final_training.ipynb` while documenting this original provenance.

## Final consistency contract

For a deployable release, these must all match:

1. final checkpoint architecture metadata;
2. `Real=0`, `Fake=1` label mapping;
3. ImageNet normalization and `224×224` preprocessing;
4. threshold `0.51` for the documented final checkpoint;
5. Streamlit and API inference through the shared package;
6. final metrics derived from the locked test evaluation.
